#  Mnemocast — Domain Model (v1)

> This document defines the core domain entities used by the **Mnemocast Engine**.  
> It is language-agnostic and acts as the source of truth for implementation.

---

## 1. Screen (Display)

Represents a **physical or virtual display** managed by Mnemocast.

### Purpose

- Identify each display uniquely
- Attach **location** and **context tags** for targeting
- Control whether a screen is active in the network

### Fields

| Field        | Type        | Required | Description |
|-------------|-------------|----------|-------------|
| `id`        | string      | yes      | Unique identifier for the screen (generated by system). |
| `name`      | string      | yes      | Human-readable label (e.g., `"Phoenix Mall - Food Court Screen 1"`). |
| `city`      | string?     | no       | City name (e.g., `"Chennai"`). |
| `area`      | string?     | no       | Area/region/neighborhood (e.g., `"Velachery"`). |
| `latitude`  | number?     | no       | Latitude for geo-targeting (optional). |
| `longitude` | number?     | no       | Longitude for geo-targeting (optional). |
| `tags`      | string[]    | yes      | Context tags (e.g., `["mall", "food_court"]`, `["office", "it_park"]`). |
| `active`    | boolean     | yes      | Whether the screen is active and should receive ads. |

> Tags are a flexible way to describe environment: `["transit", "bus_station"]`, `["hospital"]`, `["gym"]`, etc.

## 2. Campaign

Represents an **advertising campaign**, grouping rules & creatives.

### Purpose

- Define **what** is being advertised
- Control **when**, **where**, and **how often** it should appear
- Connect to multiple creatives

### Fields

| Field        | Type          | Required | Description |
|-------------|---------------|----------|-------------|
| `id`        | string        | yes      | Unique campaign identifier. |
| `name`      | string        | yes      | Campaign name (e.g., `"Morning Coffee Push"`). |
| `priority`  | integer       | yes      | Priority weight (e.g., 1–5). Higher = more likely to be shown. |
| `active`    | boolean       | yes      | Whether the campaign is enabled. |
| `startTime` | ISO8601 datetime | yes   | Campaign start time (UTC). |
| `endTime`   | ISO8601 datetime | yes   | Campaign end time (UTC). |
| `targeting` | Targeting     | yes      | Rules controlling where/when this campaign is eligible. |
| `budget`    | Budget        | yes      | Basic play-level budget for MVP. |
| `creativeIds` | string[]    | yes      | List of creative IDs belonging to this campaign. |

---

## 3. Creative

Represents a **single playable asset** (video or image).

### Purpose

- Point to an actual media file (URL)
- Provide duration and type to the playlist engine

### Fields

| Field          | Type          | Required | Description |
|---------------|---------------|----------|-------------|
| `id`          | string        | yes      | Unique creative identifier. |
| `campaignId`  | string        | yes      | The campaign this creative belongs to. |
| `type`        | enum          | yes      | `"video"` or `"image"` for MVP. |
| `durationSeconds` | integer   | yes      | Intended playback duration in seconds (e.g., 10, 15, 30). |
| `assetUrl`    | string (URL)  | yes      | Location of the media asset (e.g., CDN URL). |

**Creative type enum (MVP):**

- `video`
- `image`

---

## 4. Targeting

Rules that determine **which screens** a campaign is eligible for, and **when**.

### Purpose

- Match campaigns to screens based on:
  - Location
  - Tags
  - Day-of-week & time-of-day

### Fields

| Field        | Type        | Required | Description |
|-------------|-------------|----------|-------------|
| `cities`    | string[]    | no       | List of allowed cities. Empty = no city restriction. |
| `areas`     | string[]    | no       | List of allowed areas/neighborhoods. Empty = no area restriction. |
| `screenTags`| string[]    | no       | Screen must share at least one tag from this list. Empty = no tag restriction. |
| `daysOfWeek`| integer[]   | no       | Allowed days (1–7, e.g., 1 = Monday). Empty = all days allowed. |
| `timeBands` | TimeBand[]  | no       | Allowed time ranges during the day. Empty = all times allowed. |

### TimeBand

Represents a **time window** in a day (local time at screen/timezone).

| Field   | Type   | Required | Description |
|--------|--------|----------|-------------|
| `start`| string | yes      | Start time in `"HH:mm"` format (inclusive). |
| `end`  | string | yes      | End time in `"HH:mm"` format (exclusive). |

**Examples:**

- Morning: `{ "start": "07:00", "end": "11:00" }`
- Evening peak: `{ "start": "17:00", "end": "21:00" }`

---

## 5. Budget (MVP)

Simple **play-count-based** budget control for MVP.

### Purpose

- Limit how many times a campaign can be played in total
- Future versions can add more fields (daily limit, spend, etc.)

### Fields

| Field      | Type    | Required | Description |
|-----------|---------|----------|-------------|
| `maxPlays`| integer? | no      | Maximum allowed plays for this campaign across all screens. `null` = unlimited. |

> In MVP, `maxPlays` is global and not per-screen or per-day.

---

## 6. Playlist & Playlist Item

The **output** of the engine when a screen requests ads.

### PlaylistRequest (concept)

Not stored as entity, but for clarity:

| Field            | Type    | Description |
|------------------|---------|-------------|
| `screenId`       | string  | Which screen is asking for ads. |
| `durationMinutes`| integer | Desired playlist duration in minutes. |

### PlaylistResponse

| Field            | Type          | Description |
|------------------|---------------|-------------|
| `screenId`       | string        | Screen ID for which playlist is generated. |
| `validForSeconds`| integer       | How long this playlist should be considered valid (often `durationMinutes * 60`). |
| `items`          | PlaylistItem[]| Ordered list of creatives to play. |

### PlaylistItem

| Field            | Type    | Required | Description |
|------------------|---------|----------|-------------|
| `creativeId`     | string  | yes      | ID of the creative to play. |
| `campaignId`     | string  | yes      | ID of the parent campaign. |
| `type`           | string  | yes      | `"video"` or `"image"`. |
| `durationSeconds`| integer | yes      | How long to show this item. |
| `assetUrl`       | string  | yes      | URL to the asset to be played. |

> The engine returns a list of `PlaylistItem`s that *roughly fills* the requested duration.

## 7. PlayEvent

Represents an **ad play** that actually happened on a screen.

### Purpose

- Track delivery for:
  - Budget enforcement
  - Future reporting & analytics
- Connect screen, campaign, and creative in one record

### Fields

| Field       | Type             | Required | Description |
|------------|------------------|----------|-------------|
| `screenId` | string           | yes      | Screen on which the creative was played. |
| `campaignId`| string          | yes      | Campaign that owns the creative. |
| `creativeId`| string          | yes      | Creative that was played. |
| `startedAt`| ISO8601 datetime | yes      | Playback start timestamp (UTC). |
| `endedAt`  | ISO8601 datetime | yes      | Playback end timestamp (UTC). |

**Notes:**

- In MVP, we treat **every logged event as a valid play**.
- In future, we may add:
  - `status` (`"completed"`, `"skipped"`, `"error"`)
  - `playDurationSeconds` (actual vs intended)

## 8. Derived / Internal Concepts

These are not exposed directly via API, but important for implementation.

### 8.1 Eligibility

A campaign is **eligible** for a screen at time `T` if:

1. `campaign.active == true`
2. `startTime <= T <= endTime`
3. Targeting matches:
   - `cities` is empty **or** screen city is in `cities`
   - `areas` is empty **or** screen area is in `areas`
   - `screenTags` is empty **or** screen tags intersect `screenTags`
   - `daysOfWeek` is empty **or** current day is in `daysOfWeek`
   - `timeBands` is empty **or** local time is within at least one band
4. Budget is not exhausted:
   - `maxPlays` is `null` or `playCount(campaign) < maxPlays`

### 8.2 Priority Weighting

- `priority` is an integer (e.g., 1–5).
- Bigger number = **more frequent selection** when multiple eligible campaigns exist.
- Implementation detail (not domain): engine may repeat high-priority campaigns in its pool before random selection.

## 9. MVP Simplifications

For **MVP engine v0**:

- One global `maxPlays` budget per campaign.
- No per-screen or per-day budgets yet.
- No frequency caps per individual screen/user.
- No spending or currency-based budgets.
- Time is treated in a single default timezone for now (configurable later).
- Only two creative types:
  - `video`
  - `image`

These design choices keep the engine implementable quickly while still showing **real intelligence** and **business value**.
